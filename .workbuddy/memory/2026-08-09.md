## FM 错封面第二波：用户报「道别是一件难事」仍显示 RAPCHINA 第3期封面

  - 抽出 `TryCorrectSongCoversAsync(url, expectArrayKey)` + `ApplySongCoverCorrection(songs, list)`，每级失败返回 false 继续下一级（不再静默吞）。
  - 仍失败 → 沿用 FM 原封面（不影响播放）。
- 验证：编译 0 错误；.ccp 含新方法（TryCorrectSongCoversAsync / ApplySongCoverCorrection）+ PublicApiBases URL。

## 歌词兜底加 eapi 桌面客户端接口（commit 55cc4cc，已 clobber v0.2.0）
- 背景：用户要求参考 github.com/Replica0110/Lyrico-Plugins（Lyrico 多音乐源插件）提取网易云自家 API 作备选，明确「只要用上网易云的就够了」（不引入酷狗/QQ/汽水等第三方源）。
- Lyrico netease 插件核心：eapi 加密接口（interface.music.163.com 域名 + 桌面客户端伪装头），歌词 `/eapi/song/lyric/v1`（返回 lrc+tlyric+yrc+romalrc）。
- 实测（Node 复现）：eapi 无需匿名会话注册，随机设备指纹（deviceId 32hex + clientSign mac@@@upper8@@@@@@hex64 + osver + mode + appver 3.1.3.203419）直接通过；`/eapi/song/lyric/v1?id=1888933954&lv/tv/rv/yv=-1` 返回 code 200 + lrc 854 字符。走 interface.music.163.com 与限流的 music.163.com 不同源。
- 实现（新文件 Netease/NeteaseEapi.cs）：
  - `RequestAsync(http, path, params, userCookie)`：header{clientSign/osver/deviceId/os/appver/requestId} + e_r=true → paramsText（JsonObject 紧凑序列化，UnsafeRelaxedJsonEscaping 匹配 JS JSON.stringify）→ digest=md5("nobody"+encryptPath+"use"+paramsText+"md5forencrypt") → data=encryptPath+"-36cd479b6b5-"+paramsText+"-36cd479b6b5-"+digest → AES-128-ECB(PKCS7) 加密输出大写 hex → POST params=hex 到 interface.music.163.com → 响应体字节直接 AES 解密（注意：响应是裸 AES 密文，不是 base64——Lyrico 的 bodyBase64 是宿主封装）。
  - `FetchLyricAsync(http, songId, cookie)`：取 lrc+tlyric。
  - 常量：EapiKey="e82ckenh8dichen8"、EncryptSalt="-36cd479b6b5-"、AppVer="3.1.3.203419"、UA=NeteaseMusicDesktop。
- 兜底链变为：① 官方 /api/song/lyric（tv=0）→ ② eapi /eapi/song/lyric/v1（新）→ ③ 公共 NeteaseCloudMusicApi（zm.wwoyun.cn / iwenwiki）。
- 兼容性：eapi lrc 头部含 yrc JSON 行（{"t":0,"c":[...]}），ParseRawLrc 不以 [ 开头自动跳过，只解析标准 [mm:ss] 行，无需改动。
- 验证：C# 临时 console 工程与 Node 对拍 md5/json/digest 逐字节一致（json 与 digest 完全相同）；编译 0 错误。
- 经验：Windows 下 git bash rm -rf 会被 safe-delete 拦截（/d/ 路径识别为相对路径 \d\），用 "D:/Code/..." Windows 绝对路径可正常删。
