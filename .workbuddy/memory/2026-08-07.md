## 架构方向讨论：两层交出 → 宿主颠覆性改造
- 用户洞察："其实就两个层面——UI 层和 Core 层，把这两个交出去就能对宿主做颠覆性改造"。
- 结论：方向正确，且宿主本就是按"客户端空壳、插件自治"设计的（Core/Interfaces/IPlugin.cs:89-99 注释）。颠覆形态 = 宿主瘦成"壳 + 契约总线"，不是重写。
- 宿主内核不可插件化（5 项）：窗口/导航壳、插件总线 PluginManager（交了即循环依赖）、音频输出设备（唯一主，插件只能增强不能替换）、本地库+PlayQueue（共享状态）、DI 容器（服务根）。插件是消费者，不是拥有者。
- 交出去的分层：UI 层（IViewContributorPlugin 整页、IDiscoverTabPlugin 子tab、皮肤提供者/播放页插槽/迷你播放器 需新建）、Core 层（IOnlineMusicPlugin/ILyricsProviderPlugin 已接；IAudioEnhancer/ICoverProvider/IMenuContributor/IProtocolProvider 预留；频谱管道需新建）。契约层（反射适配器×8、FullName 匹配、跨版本 JSON 转换、PluginTypeId、SubPlugins 拆分）已就绪，改造不用重做。
- 路线建议：不重构，逐步交出——先补 4 个新契约（皮肤/播放页/频谱/通用配置 IPluginConfigurable），再交 Core 层（音效管线、文件协议 UI），最后交 UI 层（ViewContributors 渲染 → 子tab → 播放页 → 皮肤 → 迷你条）。每交一个删一段硬编码，最终宿主变纯壳。
